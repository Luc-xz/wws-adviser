# WWS Adviser 产品需求文档（PRD）

> 产品定位：面向个人投资者的轻量、可审计、移动优先的股票与基金投研助手。
>
> 文档版本：v1.1  
> 文档状态：MVP 产品基线  
> 更新日期：2026-07-18  
> 变更说明：v1.1 重定位凯利为组合层风险预算，补充信号分层（L1–L4）、校准状态机与有效期、reliability 校准 + Platt scaling、degenerate 护栏（`b`/`p` 区间/`n_eff` 门禁）、拒绝原因链，以及按动作类型的建议评价口径与回灌校准闭环。  
> 目标市场：中国 A 股、场内 ETF  
> 重要声明：本系统用于信息整理、风险分析与投资决策辅助，不保证收益，不代替持牌投资顾问，不在 MVP 阶段连接券商或自动下单。

## 1. 文档目的

本文档定义 WWS Adviser 的产品目标、用户场景、功能边界、业务规则、数据质量要求、移动端体验、风险控制和验收标准，作为产品设计、技术设计、开发排期、测试验收及后续迭代的共同基线。

本文中的优先级定义如下：

- **P0**：MVP 必须具备；缺失时核心闭环不可用。
- **P1**：MVP 后优先补齐；显著改善效率或可靠性。
- **P2**：中长期增强项；当前架构需允许扩展，但不提前实现。

## 2. 背景与问题

个人投资者的信息和决策过程通常分散在行情软件、券商 App、新闻网站、公告平台、表格和聊天模型之间，容易产生以下问题：

1. 持仓、交易记录和研究材料彼此割裂，无法形成连续的决策上下文。
2. 每日信息量过大，重大公告、行业变化和组合风险难以及时聚合。
3. 盘中提问时，通用模型不了解实时行情、实际仓位和个人风险约束。
4. 投资建议常停留在模糊的“看多/看空”，缺少仓位、触发条件、有效期和失效条件。
5. 历史建议没有留档，无法复盘预测质量、交易纪律和决策偏差。
6. 数据来源及时间不透明，可能使用陈旧、错误或不可追溯的数据。
7. 传统量化或投研平台部署较重，不适合单人、低并发和移动使用。

WWS Adviser 需要以持仓和交易账本为中心，将可靠数据、确定性计算、可配置模型和移动端报告连接成一个持续可复盘的闭环。

## 3. 产品愿景与原则

### 3.1 产品愿景

让个人投资者在开市前、交易时段、收市后和非交易日，都能获得基于最新可信数据、真实持仓及明确风险约束的分析结果，并能在手机上快速阅读和行动。

### 3.2 核心原则

1. **数据先于模型**：事实、行情和计算结果来自数据源及确定性程序，模型不得自行补造。
2. **风险先于收益**：任何仓位建议都先经过单标的、行业、组合、流动性和现金约束。
3. **条件式建议**：输出触发条件、建议区间、失效条件和有效期，避免无条件买卖结论。
4. **全链路可追溯**：保留来源、时间戳、计算输入、规则版本、提示词版本、模型及输出。
5. **移动优先**：首屏优先呈现风险和待办，详细证据按需展开。
6. **轻量部署**：个人版本保持单体服务、单数据目录和低运维成本。
7. **优雅降级**：数据陈旧、来源冲突或模型不可用时，明确提示并退化到安全能力。
8. **人做最终决策**：系统不自动下单；用户确认并记录实际行为。

## 4. 产品目标与非目标

### 4.1 MVP 目标

1. 建立准确的个人账户、持仓和交易流水账本。
2. 自动获取持仓相关的日线行情、盘中快照、公告和必要新闻。
3. 在交易日前生成开市前报告，在收市后生成复盘报告。
4. 盘中针对持仓或自选标的提供带时间戳的快速分析。
5. 对行业或公司生成有引用、可追溯的价值研究报告。
6. 基于经过校准的统计输入提供受约束的分数凯利仓位区间；输入不充分时拒绝给出伪精确结果。
7. 通过响应式 PWA 在手机和桌面共用一套产品。
8. 支持配置不同模型服务，并在模型不可用时保留基础分析能力。

### 4.2 成功指标

MVP 上线后，以连续 20 个交易日为观察周期：

| 指标 | 目标 |
| --- | --- |
| 持仓账本对账一致率 | 100%，允许用户显式确认差异 |
| 开市前报告按时生成率 | ≥ 95% |
| 收市后报告按时生成率 | ≥ 95% |
| 报告关键数值来源可追溯率 | 100% |
| 盘中快照新鲜度达标率 | ≥ 95%，以所选数据源能力为准 |
| 数据异常时危险建议拦截率 | 100% |
| 手机核心页面可用率 | 100%，无横向滚动完成主要任务 |
| 建议复盘覆盖率 | ≥ 90% |
| 用户完成一次日常查看所需时间 | 开市前摘要 ≤ 3 分钟，盘中快速建议 ≤ 30 秒阅读 |

收益率不作为 MVP 成功指标。首期重点验证数据、纪律、可追溯性和使用效率。

### 4.3 MVP 非目标

- 自动交易、条件单或券商账户托管。
- 保存券商密码、短信验证码或交易口令。
- 多用户、团队协作、社交、跟单或公开荐股。
- Tick 级全市场采集、高频交易或毫秒级信号。
- 全市场实时扫描和复杂选股平台。
- 大规模模型训练或自建通用大模型。
- 原生 iOS/Android App；MVP 采用 PWA。
- 保证盈利、承诺准确率或给出无风险收益结论。
- 依赖未经验证的模型主观概率直接计算凯利仓位。

## 5. 用户与使用环境

### 5.1 目标用户

MVP 仅服务于产品所有者本人：有一定股票/基金投资经验，持有数量有限，希望建立更系统的研究、风险控制和复盘习惯，但不希望维护复杂基础设施。

### 5.2 典型环境

- 通勤途中使用手机查看通知、风险和行动摘要。
- 盘中使用手机快速询问某一持仓是否需要处理。
- 晚间使用电脑查看完整复盘、修正交易记录。
- 周末使用电脑或平板开展公司及行业深度研究。
- 服务运行在个人电脑、NAS 或轻量云服务器。

### 5.3 核心用户任务

1. 录入或导入交易，随时看到可信的当前持仓。
2. 开盘前快速知道今天最重要的风险和观察事项。
3. 盘中获得基于最新快照及真实仓位的条件式建议。
4. 收盘后理解盈亏来源、行为偏差和次日待办。
5. 周末完成一份有数据出处的公司或行业研究。
6. 调整模型、风险偏好、通知渠道和报告时间。

## 6. 核心业务闭环

```text
录入/导入交易
      ↓
计算持仓、现金与成本
      ↓
采集行情、公告、基金披露和新闻
      ↓
生成指标、风险暴露与研究证据
      ↓
开市前 / 盘中 / 收市后 / 深度研究分析
      ↓
用户阅读、决策并记录实际操作
      ↓
评估建议、交易执行和预测偏差
      └──────────────→ 下一周期校准
```

## 7. 信息架构与移动端导航

### 7.1 底部主导航

移动端使用五个一级入口：

1. **首页**：组合摘要、今日建议、风险告警、最新报告。
2. **持仓**：账户、持仓、交易流水、自选列表。
3. **助手**：盘中问询、通用问询、历史会话。
4. **研究**：公司研究、行业研究、报告库和证据来源。
5. **设置**：数据源、模型、风险、通知、调度、备份与安全。

桌面端沿用相同信息架构，可将导航展示为侧边栏，并增加适合大屏的表格和图表。

### 7.2 首页层级

首页自上而下展示：

1. 数据状态条：当前市场状态、最近更新时间、是否延迟。
2. 组合摘要：总资产、现金比例、当日盈亏、累计盈亏。
3. 最高优先级风险：超限仓位、重大公告、数据异常。
4. 今日行动卡：建议动作、目标区间、触发条件和有效期。
5. 持仓概览：涨跌、仓位、成本和风险标签。
6. 最新报告与一键快速提问。

## 8. 功能需求

### 8.1 账户、持仓与交易管理

#### FR-PORT-001 单账户管理（P0）

系统应支持一个个人投资账户，并记录账户名称、币种、初始现金、当前现金、总资产和更新时间。

**验收标准：**

- 用户可创建、编辑和停用账户。
- MVP 默认人民币，不进行跨币种折算。
- 总资产等于现金与所有持仓最新市值之和。
- 关键金额使用十进制定点计算，不使用二进制浮点直接结算。

#### FR-PORT-002 交易流水（P0）

系统应支持手工录入和 CSV 导入买入、卖出、分红、派息、手续费、税费、拆分、合并、申购、赎回及现金调整记录。

**验收标准：**

- 流水包含标的、方向、成交日期时间、数量、单价、费用、账户和备注。
- 股票买卖数量需按适用市场规则校验；特殊品种允许配置例外。
- 导入前显示预览、校验错误和重复项，用户确认后才入账。
- 通过外部流水号或字段指纹避免重复导入。
- 流水修改和删除保留审计记录，并触发持仓重算。

#### FR-PORT-003 持仓计算（P0）

系统应从交易流水确定性计算当前数量、可用数量、平均成本、累计费用、已实现盈亏、未实现盈亏和持仓权重。

**业务规则：**

- 成本法在设置中明确，MVP 默认移动加权平均成本法。
- 分红、拆分和复权因素需按品种处理。
- 用户可执行“对账调整”，但必须填写原因并保留调整前后数值。

**验收标准：**

- 对预设交易样本，数量、成本、现金和盈亏计算结果与测试基准一致。
- 任意历史流水变化后，相关日期之后的持仓快照可重建。
- 没有最新价格时保留上一次估值并明确标记时间，不显示为实时值。

#### FR-PORT-004 标的与自选（P0）

系统应支持 A 股和场内 ETF，维护代码、名称、市场、类型、交易状态、所属行业和数据源映射。用户可以加入或移除自选标的。

### 8.2 市场、公告与信息采集

#### FR-DATA-001 交易日历与市场状态（P0）

系统应识别交易日、休市日、集合竞价、连续竞价、午间休市和闭市状态。交易时间默认采用 Asia/Shanghai，并允许按官方临时安排更新。

#### FR-DATA-002 日线与净值数据（P0）

系统应采集持仓、自选、基准指数和相关行业 ETF 的历史日线。

**验收标准：**

- 保存来源时间、抓取时间、交易日期和复权口径。
- 任务支持幂等重试，不因重复执行生成重复记录。
- 发现缺口、重复、异常价格或前后不一致时生成数据质量告警。
- 不得将尚未发布或缓存的数据标记为实时。

#### FR-DATA-003 盘中行情快照（P0）

系统应按需获取持仓、自选及用户当前查询标的的最新行情快照，包括最新价、涨跌幅、成交量、成交额、盘口可用字段、行情时间和数据源。

**业务规则：**

- “实时”仅在数据许可和源能力支持时使用；否则显示明确的延迟级别。
- MVP 不持续存储全市场 Tick 数据。
- 行情过期阈值可配置，默认交易时段 180 秒。
- 超过阈值、时间戳异常或关键字段缺失时，禁止给出依赖即时价格的具体交易数量。

#### FR-DATA-004 公告与正式披露（P0）

系统应优先采集持仓及自选标的的交易所公告、公司公告、财报和基金公告，保存标题、发布主体、发布时间、来源链接、文档哈希和本地文件状态。

**验收标准：**

- 相同公告不会因多次抓取而重复展示。
- 报告引用公告时可打开原始来源或本地归档。
- 公告摘要明确区分原文事实和模型概括。

#### FR-DATA-005 新闻与行业信息（P0）

系统应采集少量经过配置的可靠新闻和行业信息源，按标的、行业、主题、发布时间和可信等级分类。

**业务规则：**

- 新闻不得覆盖或改写官方公告事实。
- 聚合转载应尽量追溯首发来源。
- 社交媒体仅可作为低可信情绪信号，MVP 默认关闭。
- 必须遵守数据源授权、频率、版权和服务条款。

#### FR-DATA-006 数据源与质量状态（P0）

系统应为所有用于分析的关键数据保存：`source`、`source_url`、`published_at`、`market_time`、`fetched_at`、`quality_status` 和内容或记录哈希。

质量状态至少包括：正常、延迟、缺失、冲突、解析失败、来源不可用。

关键价格或公司行动发生来源冲突时，优先采用官方或授权等级更高的数据，并记录冲突。无法消解时，相关建议降级。

### 8.3 分析与组合风控

#### FR-ANL-001 组合摘要（P0）

系统应计算总资产、现金比例、当日和累计盈亏、持仓集中度、行业暴露、单标的贡献、波动率及最大回撤等指标。缺少足够样本时应显示“样本不足”，不得补造指标。

#### FR-ANL-002 风险规则（P0）

用户可配置以下软限制和硬限制：

- 单股票/基金最大仓位。
- 单行业最大仓位。
- 前 N 大持仓集中度。
- 最低现金比例。
- 组合目标波动率。
- 最大可接受回撤。
- 单次交易最大资金比例。
- 高波动、低流动性、ST/退市风险等标的限制。

软限制触发警告并要求解释；硬限制不得被自动建议突破。用户仍可在系统外自行交易，但系统需记录该行为偏离风险规则。

#### FR-ANL-003 信号、概率输入与凯利资格（P1）

系统应通过可回测的方法生成预期胜率、平均盈利、平均亏损、预测区间和样本量。每个信号版本需记录训练/统计窗口、适用品种、交易成本假设、样本外表现和校准状态。

**凯利定位：** 凯利在本系统中主要用于**组合层风险预算分配**，而非个股下注。股票是连续价格过程且可部分平仓，二项近似凯利对“全输/全赢的离散赌注”才严格成立；将其用于个股精确下注只是一种粗糙类比。因此凯利在体系内扮演“是否应向某类信号/某行业/某标的提升风险预算上限”的软提示（分数折扣已体现其辅助权重），个股的目标新增仓位仍主要由硬风险规则与再平衡偏离度驱动。

**概率来源原则：** `p` 的校准对象是**信号规则在适用的全市场标的集合上的历史回测表现（横截面与时间序列并集）**，不是用户自己持有的某只股票。用户个体交易记录样本稀薄，无法支撑统计意义上的概率校准；以全市场同类信号为校准对象，从根源上规避个人样本不足问题。

**信号类型分层（按可校准性）：**

| 层级 | 信号类型 | `p` 来源 | 凯利资格 |
| --- | --- | --- | --- |
| L1 | 规则化/机械信号（如突破N日均线+量能） | 全市场回测，样本充足 | 默认有资格 |
| L2 | 基本面因子信号（如低估值+高质量分位） | 横截面分组回测 | 有资格，需滚动校准 |
| L3 | 事件驱动信号（如特定公告类型后反应） | 事件匹配回测，样本中等 | 条件性资格，按事件类目 |
| L4 | 模型语言判断 | —— | 永远无资格 |

**校准状态机：** 信号校准状态为 `UNCALIBRATED → CALIBRATING → CALIBRATED(oos_pass) → STALE → DECAYED`，并设有校准有效期（默认 60 个交易日，可配置）。到期自动转为 `STALE`，凯利拒绝使用直到重新跑样本外并通过。校准除统计命中率外，还须验证**概率校准**：对历史预测概率分箱，实际命中率是否落在预测概率附近（reliability）；系统性地高估概率的信号须拒绝或经 Platt scaling 修正后重评，修正记录入版本。

模型语言输出不得直接作为胜率输入，也不得经任何间接路径进入 `p`。`Signal` 记录须带 `signal_class ∈ {L1,L2,L3}`，`p` 字段只能在回测/校准服务内写入，模型 Gateway 无权写。没有可靠样本外检验、校准未通过或已过期的信号，均不具备凯利资格。

#### FR-ANL-004 受约束的分数凯利仓位（P1）

凯利定位为**组合层风险预算**，而非单笔交易的精确资金分配。二项近似下的原始凯利比例为：

```text
f* = (b × p - (1 - p)) / b
```

其中 `p` 为经校准的获利概率，`b` 为平均盈利与平均亏损之比。需明确：这是**离散赌注近似**，对连续价格过程仅作风险预算参考，不可解读为可精确优化的真实最优仓位。`p` 的校准对象是**全市场同类信号**的历史回测，而非用户个体持仓表现；`p` 必须带置信区间，输入形式为 `(p_low, p_mid, p_high)`（Wilson 区间），凯利因此**报区间而非单点**。

系统最终建议采用：

```text
目标仓位 = clip(凯利折扣 × f* × 置信折扣 × 流动性折扣,
                0,
                单标的上限)
```

并继续受到行业上限、组合风险、现金下限、交易成本、最小交易单位和当前仓位约束。

**默认规则：**

- 凯利折扣默认 0.20，可配置范围 0.10～0.25。该折扣同时承担三重修正：“凯利假设不成立（连续过程 vs 离散赌注）”“`p` 的估计误差”“个人风险厌恶程度高于对数效用”——它是对真实不确定性无法精确量化的**诚实地板**，而非精确推导值，用户不得将其理解为精确计算结果。
- 原始凯利为负时，新增目标仓位为 0；系统不据此自动生成做空建议。

**Degenerate 护栏（纯函数 + 单测 + 属性测试覆盖）：**

- **`b` 的边界**：`b ≤ 0`（平均亏损 ≥ 平均盈利）时 `f*` 无意义，输出 0 并记原因 `non_positive_payoff`；`b` 极端（`b > 10` 或 `b < 0.1`）时 `f*` 对 `b` 极敏感、单点估计不可靠，强制只输出区间下限或拒绝，记原因 `extreme_payoff`，不允许给中位值。
- **`p` 置信区间化**：用 `p_low` 算保守 `f*`、`p_mid` 算中位，报告区间而非单点（区间的统计学来源即 Wilson 区间）。当置信区间过宽（校准本身不确定）时，凯利输出进一步折扣或拒绝，记原因 `wide_p_interval`。
- **有效样本门禁**：引入有效样本数 `n_eff`，对重叠信号做衰减以避免同一信号在相邻日期重复计入。`n_eff < 30` 拒绝（原因 `insufficient_samples`）；`30 ≤ n_eff < 100` 强制半折扣并标记 `low_confidence`；`n_eff ≥ 100` 正常。**样本外 `n_eff` 须独立达标**，不得拿样本内总量凑。
- **概率校准门禁**：`p` 须通过 reliability 校准（见 FR-ANL-003 校准状态机）。校准未通过或状态为 `STALE`/`DECAYED` 的信号，凯利拒绝使用，记原因 `calibration_*`。

**输出与展示规则：**

- 输出区间而非单点，避免伪精确；任何拒绝/折扣必须保留**可审计的原因链**（如 `n_eff=24 → 拒绝`、`calibration=STALE → 拒绝`、`b=0.05 → extreme_payoff → 仅区间下限`），原因链写入 `Advice` 记录。
- 数据过期或市场状态异常时，不提供凯利新增仓位，原因 `data_stale`/`market_abnormal`，不静默隐藏。
- 建议必须同时展示计算输入、折扣、约束、最终区间、失效条件和（若有）拒绝/折扣原因链。

**验收标准：**

- 给定固定输入，计算结果可重复且有单元测试覆盖；degenerate 场景（`b≤0`、极端 `b`、宽 `p` 区间、`n_eff` 各档）均有针对性测试。
- 任一硬性风险限制均能截断理论凯利仓位。
- 用户能看到“理论仓位为何被调整为最终仓位”，以及任何拒绝/折扣的完整原因链。
- 系统不得以大模型主观置信度替代统计概率。

### 8.4 开市前报告

#### FR-REP-001 自动生成（P0）

系统应在每个交易日开市前按配置时间生成报告，默认 08:30 开始、09:00 前完成。若数据尚未发布，应标注截止时间，不等待不确定的数据无限阻塞。

#### FR-REP-002 报告内容（P0）

开市前报告至少包含：

1. 数据截止时间和完整性状态。
2. 当前组合、现金和风险摘要。
3. 隔夜重要公告、财报、监管和行业事件。
4. 停复牌、除权除息、解禁等持仓相关公司行动。
5. 各持仓今日动作建议：保持、观察、减少、条件式增加或退出观察。
6. 建议目标仓位区间、触发条件、失效条件及证据。
7. 当日重点观察清单和风险日历。

#### FR-REP-003 报告验收（P0）

- 没有交易日时不生成普通开市前报告，除非用户手动触发。
- 每条重要事实均可追溯到来源。
- 行情和公告数据截止时间清晰可见。
- 任一建议不得突破硬风险限制。
- 数据严重缺失时生成“数据异常摘要”，不伪装为正常建议。

### 8.5 盘中快速问询

#### FR-CHAT-001 自然语言问询（P0）

用户可询问持仓、自选或指定标的，例如“现在需要减仓吗”“这次上涨能追吗”“如果买入 500 股会怎样”。系统应识别标的和意图；存在代码歧义时要求用户确认。

#### FR-CHAT-002 低延迟分析链路（P0）

系统按以下顺序处理盘中请求：

1. 判断交易日和市场状态。
2. 获取最新行情快照并检查时间戳。
3. 读取持仓、现金、交易行为和风险限制。
4. 运行确定性指标、风险和仓位计算。
5. 检索已缓存的公告、基本面及事件证据。
6. 由快速模型组织条件式回答。

#### FR-CHAT-003 回答格式与安全降级（P0）

盘中回答必须展示：行情时间、延迟状态、当前仓位、建议动作、建议幅度或目标区间、触发条件、失效条件、证据摘要和有效期。

默认有效期为 10 分钟或直到价格突破建议中设定的失效条件，以先到者为准。

以下情况只允许返回事实或风险提示，不提供即时交易数量：

- 行情超过新鲜度阈值。
- 关键数据缺失或多个关键来源冲突。
- 持仓账本未完成对账。
- 模型输出与确定性风险规则冲突。
- 市场处于无法正确识别的异常状态。

#### FR-CHAT-004 性能（P0）

在行情源和模型正常时，从提交问题到首屏可读答案的目标延迟：P50 ≤ 5 秒，P95 ≤ 12 秒。若深度分析需要更长时间，先返回数据快照与基础风险结果，再异步补充。

### 8.6 收市后复盘

#### FR-REV-001 自动生成（P0）

系统应在交易日收市且当日行情基本完整后生成复盘，默认 16:00 开始、17:00 前完成。当日数据源缺失或日线未就绪时，报告需标记“待更新”，可在数据补齐后补算。

#### FR-REV-002 复盘内容（P0）

1. 当日资产、盈亏和基准表现。
2. 个股、基金、行业及现金对收益的贡献。
3. 当日交易的成交成本、费用、滑点及相对 VWAP 的执行质量（有足够数据时）。
4. 开市前和盘中建议的触发、失效及结果。
5. 实际行为与计划、风险规则的偏差。
6. 组合风险变化、超限项和待处理事项。
7. 次日关注事件和需要用户确认的数据问题。

#### FR-REV-003 建议评价（P1）

系统应保存建议时的数据快照，并在设定观察窗口后评价方向、风险、触发条件和仓位建议。不得只按短期涨跌简单判断建议“正确”或“错误”；评价口径需按建议类型定义并版本化。

**按建议动作类型的评价口径（写入《分析与风控规范》，版本化）：**

| 动作类型 | 评价窗口 | 主评价口径 | 次口径 |
|---|---|---|---|
| 条件式增加 | 触发后 5–20 交易日，或直到失效 | 触发条件是否真的出现；出现后方向是否对 | 区间内最大不利波动 |
| 减少 | 失效条件前 | 减仓后该标的相对基准的超额（避免“卖了就涨”的道德化误判） | 是否降低了组合波动 |
| 观察 | 不评价收益 | 后续是否进入可操作状态 | 信息是否变充分 |
| 退出观察 | 30–60 交易日 | 假设失效是否被市场证伪 | —— |
| 暂停建议 | 不评价收益 | 数据恢复后是否本该给出建议 | 间接衡量数据降级频率 |

**核心原则：** 条件式建议的评价本质是评价“条件设计是否合理 + 触发后方向”，而非“涨没涨”——一个“若跌破 X 则减仓”的建议，即便后来上涨，只要“跌破 X”未发生，该建议即合理（避免了错误触发）。

**评价回灌校准：** 评价结果须回灌至信号校准——某类信号的历史建议表现差 → 降低其 `p` 或转入 `DECAYED`。由此接通“凯利输入 ↔ 建议评价 ↔ 信号校准”闭环，即为 PRD 第 6 节“下一周期校准”的具体落地。

### 8.7 公司与行业深度研究

#### FR-RES-001 研究任务（P0）

用户可在非交易日或任意时段创建公司/行业研究任务，选择研究范围、时间跨度、对标对象和深度。任务可异步运行，用户离开页面后继续执行。

#### FR-RES-002 公司研究报告（P0）

公司报告至少包含：

- 公司概览、商业模式和收入结构。
- 行业位置、竞争格局和护城河。
- 治理、股东与管理层关键事项。
- 收入、利润、现金流、资产负债和资本回报趋势。
- 关键经营指标及同业对比。
- 估值：历史分位、可比公司和情景分析；数据充分时可提供 DCF。
- 催化剂、主要风险、反方观点和关键待验证假设。
- 事实、推断与模型判断的显式区分。
- 引用、数据截止时间和生成配置。

#### FR-RES-003 行业研究报告（P0）

行业报告至少包含：

- 行业定义、市场规模、增速和周期位置。
- 产业链、价值分配和关键成本/价格驱动。
- 竞争格局、进入壁垒、供需和政策影响。
- 代表公司与核心指标对比。
- 上行、中性、下行情景。
- 催化剂、结构性风险和跟踪指标。
- 引用、数据截止时间和生成配置。

#### FR-RES-004 引用与事实核查（P0）

- 财务数据优先引用正式财报、公告和官方统计。
- 每个关键结论需关联至少一个证据；关键争议事实尽量双源验证。
- 引用可定位到文档或网页，必要时包含页码/章节。
- 无法验证的信息明确标记“未证实”，不得写成确定事实。
- 生成报告时保存来源清单及内容哈希，确保未来可复盘。

### 8.8 模型配置与路由

#### FR-MODEL-001 可配置服务（P0）

系统应支持 OpenAI-compatible 模型服务，并允许配置：服务商名称、Base URL、模型名、密钥引用、温度、最大输出、超时和重试次数。

密钥只通过环境变量或安全凭据存储引用，默认不以明文写入数据库、日志、导出文件或前端本地存储。

#### FR-MODEL-002 场景路由（P0）

用户可以分别为以下任务选择模型：

- 盘中快速问询。
- 开市前报告。
- 收市后复盘。
- 公司/行业深度研究。
- 文档摘要与信息抽取。

#### FR-MODEL-003 可测试与可降级（P0）

- 设置页提供连接测试和最小示例调用。
- 模型不可用时，持仓、行情、指标、风险和规则报告仍可用。
- 任务失败时显示失败环节和可重试操作，不丢失已完成的中间结果。
- 模型输出不得覆盖确定性计算字段；冲突时以程序计算和风险规则为准。

#### FR-MODEL-004 调用审计（P0）

记录任务类型、模型、参数、提示词模板版本、输入证据 ID、开始/结束时间、Token 用量、估算费用、状态和错误码。默认不在普通日志中记录完整敏感持仓提示词。

### 8.9 通知与调度

#### FR-NOTIFY-001 通知渠道（P0）

MVP 至少实现一种轻量通知渠道，并保留企业微信机器人、Server 酱和邮件的可插拔接口。通知失败不应导致报告任务失败。

#### FR-NOTIFY-002 通知事件（P0）

支持以下通知：

- 开市前报告完成或失败。
- 收市后复盘完成或失败。
- 重大公告或硬风险限制触发。
- 数据源持续不可用或数据严重过期。
- 异步研究报告完成。

#### FR-NOTIFY-003 隐私模式（P0）

用户可控制锁屏通知是否显示股票名称、金额、盈亏和建议动作。隐私模式下只显示“有 2 项风险需要查看”等摘要，点击后登录查看。

#### FR-SCHED-001 定时任务（P0）

系统使用交易日历和 Asia/Shanghai 时区执行任务。任务需要具备唯一运行 ID、幂等性、超时、有限重试、运行历史和手动补跑能力。同一任务同一业务日期不得并发重复执行。

### 8.10 PWA 与移动体验

#### FR-PWA-001 可安装（P0）

应用应包含 Web App Manifest、图标和 Service Worker，可从主流移动浏览器添加到桌面并以独立窗口启动。

#### FR-PWA-002 响应式布局（P0）

- 支持主流手机宽度 360px～430px。
- 核心任务无需横向滚动。
- 主要触控目标不小于 44×44 CSS 像素。
- 支持浅色和深色主题。
- 手机端表格转为卡片或冻结关键列。

#### FR-PWA-003 弱网与离线（P0）

- 缓存应用外壳和用户最近主动打开的报告。
- 离线时明确显示离线状态和缓存生成时间。
- 不缓存或伪造“实时行情”；离线时关闭盘中即时建议。
- 恢复网络后可手动重试或自动刷新非敏感摘要。

#### FR-PWA-004 报告阅读（P0）

报告先显示一屏摘要，再按“行动—风险—依据—详细数据—来源”展开。支持目录、段落折叠、字号适配、复制链接/文本和导出。

### 8.11 设置、备份与恢复

#### FR-SET-001 设置项（P0）

设置页应覆盖数据源、模型、风险限制、交易成本、任务时间、通知、隐私、时区及数据保留期限。

#### FR-BACKUP-001 备份（P0）

系统应支持手动备份，并可配置每日自动备份业务数据库、配置、报告元数据和必要文档索引。密钥默认不进入普通备份。

#### FR-BACKUP-002 恢复（P0）

恢复前校验备份版本和完整性，恢复后自动执行数据库校验与持仓重算。恢复操作必须二次确认，并在覆盖前创建当前状态快照。

## 9. 关键业务规则

### 9.1 市场时间

- 所有业务时间按 Asia/Shanghai 存储和展示，同时数据库建议保留 UTC 时间戳。
- 系统必须通过交易日历判断工作流，不能只按周一至周五推断。
- 交易时段判断需覆盖集合竞价、连续竞价、午休、收盘集合竞价和临时休市。
- 非交易时段的“当前价”必须显示最后成交时间或净值日期。

### 9.2 建议动作词汇

MVP 使用有限、可解释的动作集合：

| 动作 | 含义 |
| --- | --- |
| 保持 | 当前仓位仍在目标区间内，无需动作 |
| 观察 | 信息或信号不足，等待明确条件 |
| 条件式增加 | 仅在指定价格、事件和风险条件满足时增加 |
| 减少 | 当前仓位或风险暴露高于目标区间 |
| 退出观察 | 投资假设失效或风险超过允许范围 |
| 暂停建议 | 数据、模型或账本状态不满足建议条件 |

所有动作需对应理由、目标仓位区间、触发条件、失效条件和有效期。对基金申赎还需提示确认延迟、净值未知和费用规则。

### 9.3 建议优先级

1. 数据和账户完整性问题。
2. 硬风险限制和重大合规/退市风险。
3. 影响投资假设的正式公告。
4. 组合再平衡及仓位建议。
5. 短期价格、技术或情绪信号。

低优先级信号不得覆盖更高优先级风险。

### 9.4 数据新鲜度

默认阈值如下，用户可在数据源能力范围内调整：

| 数据 | 正常标准 | 超时处理 |
| --- | --- | --- |
| 盘中行情 | 行情时间距当前 ≤ 180 秒 | 禁止具体即时交易数量，显示延迟 |
| 日线 | 最近已结束交易日数据完整 | 报告标记不完整并降低建议等级 |
| 公告 | 开市前任务覆盖至报告截止时间 | 显示检索截止时间 |
| 新闻 | 展示来源发布时间和抓取时间 | 不以陈旧新闻解释即时波动 |
| 基金净值 | 最新官方披露净值 | 明确净值日期，不标记实时 |
| 财报 | 最新正式披露期 | 显示报告期，不用预告替代正式值 |

### 9.5 数据可信等级

1. L1：交易所、监管、公司/基金正式披露、官方统计。
2. L2：授权行情或专业数据供应商。
3. L3：可信新闻机构和行业协会。
4. L4：聚合站、转载和其他辅助来源。
5. L5：社交媒体或未经证实信息。

事实冲突时默认采用更高等级；同等级冲突需展示差异或暂停相关结论。

## 10. 报告统一规范

每份自动或手动报告都应包含：

- 报告类型、业务日期和生成时间。
- 数据截止时间、数据完整度和异常提示。
- 面向用户的一屏摘要。
- 关键结论和建议动作。
- 风险、反方观点和失效条件。
- 关键指标及确定性计算结果。
- 信息来源、链接和发布日期。
- 使用的数据快照 ID、规则版本、模型、提示词模板版本。
- “仅供个人研究和决策辅助”的声明。

报告内容需明确标注三种性质：

- **事实**：可由引用直接验证。
- **计算**：由已记录输入和规则可重复得到。
- **判断**：模型或分析逻辑的解释性结论。

## 11. 核心数据对象

| 对象 | 主要内容 |
| --- | --- |
| Account | 账户、币种、现金和状态 |
| Instrument | 标的代码、市场、类型、名称和行业 |

| MarketQuote | 行情字段、市场时间、来源和质量状态 |
| NAVRecord | 基金净值、净值日期、披露时间和来源 |

## 12. 非功能需求

### 12.1 性能

- 手机首页在普通 4G 网络、缓存应用资源后，目标 3 秒内展示已有摘要。
- 常规 API 在本地部署环境下 P95 ≤ 500ms，不包含外部数据源和模型等待。
- 盘中回答性能遵循 FR-CHAT-004。
- 长报告异步生成，不阻塞页面和其他定时任务。

### 12.2 可用性与可靠性

- 单个外部数据源或模型故障不得导致整个应用不可用。
- 所有采集和报告任务可安全重试，并记录失败原因。
- 关键写入使用事务；数据库异常时不得产生半条交易。
- 应用重启后未完成任务可识别并恢复或标记失败。

### 12.3 安全与隐私

- 即使是单用户部署，也必须启用身份验证。
- 公网部署必须使用 HTTPS；推荐通过 Tailscale 等私有网络访问。
- 会话 Cookie 使用 `HttpOnly`、`Secure` 和合理的 `SameSite` 策略。
- 密码使用成熟的慢哈希算法；支持长密码，P1 支持 Passkey。
- API 密钥不返回前端、不写普通日志、不进入默认导出和备份。
- CSV、文档和模型响应均视作不可信输入，防止公式注入、路径穿越和提示词注入。
- 发送给外部模型的数据应最小化；设置页明确显示会发送哪些内容。
- 不采集或保存券商登录凭据。

### 12.4 可审计性

- 交易、风险设置、模型设置和建议的关键变更写入审计日志。
- 每条建议可还原当时的持仓、行情、证据、规则、模型和提示词版本。
- 日志需关联请求 ID/任务 ID，敏感信息脱敏。

### 12.5 可维护性

- 采用模块化单体，数据采集器、模型服务和通知渠道使用适配器接口。
- 业务计算与模型提示分离，关键算法有单元测试。
- SQLite 到 PostgreSQL、内存缓存到 Redis 的升级不改变上层业务接口。
- 所有数据库结构变化通过迁移脚本完成。

### 12.6 可访问性

- 关键状态不仅用红绿颜色表达，还需使用文字或图标。
- 主要文字支持系统字体放大。
- 交互元素具有可识别标签，满足基础键盘和屏幕阅读器使用要求。

## 13. 轻量技术约束

本节是产品对实现复杂度的约束，不替代详细技术设计。

### 13.1 MVP 推荐形态

- 前端：Vue 3 + TypeScript 响应式 PWA。
- 后端：FastAPI 模块化单体。
- 业务数据库：SQLite，启用 WAL 和外键约束。
- 历史行情：Parquet；分析优先 Polars，必要时使用 DuckDB。
- 调度：进程内调度器，但需处理单实例锁和任务幂等。
- 缓存：进程内 TTL 缓存。
- 部署：一个应用容器与一个持久化数据目录。

### 13.2 初期不引入

MVP 不引入微服务、Kubernetes、Kafka、独立 Redis、独立向量数据库或复杂数据湖。需要扩展时，通过已定义的适配器和存储接口逐步替换。

## 14. 异常与降级策略

| 异常 | 产品行为 |
| --- | --- |
| 行情源不可用 | 展示上次数据和时间；停止即时交易数量建议 |
| 公告源不可用 | 报告标记信息检索不完整，不声称“无重大公告” |
| 多源关键数据冲突 | 展示冲突，按可信等级处理；无法确认时降级建议 |
| 模型不可用 | 输出确定性持仓、行情、指标和风险规则报告 |
| 模型回答违反硬限制 | 拦截冲突内容，以规则结果重写或暂停建议 |
| 数据库不可写 | 禁止提交交易或设置，提示备份与恢复，不静默丢失 |
| 定时任务错过 | 记录错过状态；恢复后允许手动补跑，不重复通知 |
| 网络中断 | 展示缓存报告及时间，关闭需要实时数据的操作 |
| 持仓未对账 | 清晰标记；允许研究，不给出精确调仓数量 |
| 数据源未就绪 | 使用最后已确认数据并标日期，报告后续补算 |

## 15. 分析与建议防线

每次建议按以下顺序通过防线：

1. **身份和权限检查**：仅本人可访问持仓及报告。
2. **账本检查**：账户是否完成对账，交易是否存在待确认项。
3. **数据质量检查**：行情、公告和关键财务数据是否新鲜、完整、一致。
4. **市场规则检查**：交易状态、停牌、涨跌停、最小交易单位等。
5. **确定性计算**：指标、仓位、现金、费用和风险暴露。
6. **风险规则检查**：软硬上限和组合约束。
7. **模型解释**：仅基于结构化结果和已检索证据生成文字。
8. **输出校验**：数值一致性、引用存在性、动作词汇和有效期检查。
9. **审计落库**：保存输入快照、版本、输出和状态后再展示。

任一关键防线失败时，系统进入相应降级模式。

## 16. MVP 验收场景

### AC-01 首次使用与持仓建立

用户完成登录、创建账户、设置初始现金、导入一份包含买卖和费用的 CSV。系统预览并拒绝错误行，确认后正确显示现金、数量、成本和盈亏，重复导入不会生成重复流水。

### AC-02 开市前报告

在一个正常交易日，系统按时采集最新已知行情、公告和相关信息，生成移动端可读报告。每个核心结论可查看证据，所有建议遵守风险限制；公告源失败时报告明确标记不完整。

### AC-03 盘中快速问询

用户在连续竞价时询问一只持仓。系统获取最新快照，在目标时间内返回当前仓位、条件式动作、区间、触发/失效条件、行情时间和有效期。将行情时间人为设置为过期后，系统停止提供具体交易数量。

### AC-04 收市后复盘

用户当日有至少一笔交易。收盘后系统正确计算盈亏贡献和风险变化，关联当天建议与实际操作，并标记计划偏差。数据源未就绪时不错误计算当日最终收益。

### AC-05 公司研究

用户发起公司研究，系统异步生成包含业务、财务、行业、估值、催化剂、风险和反方观点的报告。关键财务数字可追溯至正式披露；无来源结论被标记为判断或未证实。

### AC-06 模型故障

关闭模型服务后，系统仍能登录、管理交易、更新行情、展示持仓和确定性风险摘要；报告任务显示可理解的降级状态并可重试。

### AC-07 分数凯利约束

使用固定的已校准概率和盈亏比输入，系统可重复计算理论凯利值。单标的或行业上限低于理论值时，最终建议被正确截断；移除校准标记后系统不再给出凯利新增仓位。

### AC-08 PWA 与弱网

用户可将应用安装到手机桌面。断网后可打开最近访问的报告，并看到缓存时间；盘中行情和快速建议入口显示不可用。恢复网络后可刷新至最新状态。

### AC-09 备份与恢复

用户创建备份，新增若干交易后执行恢复。系统二次确认、自动保护当前状态、恢复成功并重算持仓；模型密钥不出现在普通备份文件中。

## 17. 迭代计划

### 阶段 0：工程基础

- 应用骨架、配置、数据库迁移、认证和审计。
- PWA 外壳、移动导航和设计基线。
- 数据源、模型和通知适配器接口。
- 测试、备份和本地部署脚本。

**退出条件：** 手机可安装并安全登录，服务可持久化数据，基础任务可运行和观察。

### 阶段 1：持仓—报告 MVP

- 账户、交易流水、CSV 导入和持仓计算。
- 交易日历、日线/净值、盘中快照。
- 公告和少量新闻源。
- 首页、持仓页、开市前报告、收市后复盘。
- 一种通知渠道、模型配置和故障降级。

**退出条件：** 连续 10 个交易日稳定形成“交易—持仓—报告—复盘”闭环。

### 阶段 2：量化风险与盘中建议

- 信号回测、概率校准和成本假设。
- 受约束的分数凯利仓位。
- 盘中快速问询和有效期控制。
- 建议结果评价和行为偏差分析。

**退出条件：** 凯利输入通过样本外校准，硬风险限制和数据降级场景全部通过自动测试。

### 阶段 3：深度研究与体验增强

- 公司/行业研究、结构化引用和研究模板。
- 可比估值、DCF 情景分析和长期跟踪指标。
- 多数据源交叉验证、Web Push、Passkey 和报告导出。

**退出条件：** 抽样报告关键事实均可追溯，移动端阅读和异步任务体验稳定。

### 阶段 4：按需扩展

仅在真实使用出现瓶颈时考虑 PostgreSQL、Redis、独立任务执行器、原生 App 或多账户能力。

## 18. 上线门槛

MVP 进入个人真实使用前，必须满足：

- 持仓计算测试覆盖买入、卖出、费用、分红、拆分、申赎和调整。
- 风险规则、凯利计算及降级逻辑有自动测试。
- 所有报告关键数字可追溯到数据记录或确定性计算。
- 交易时段行情过期时能可靠阻止具体交易数量建议。
- 模型不可用或生成异常时不会破坏业务数据。
- PWA 在至少一台 iOS 和一台 Android 设备或等效浏览器环境完成验证。
- 完成一次备份恢复演练。
- 公网部署时完成 HTTPS、身份验证、会话和密钥检查。
- 数据源使用方式符合相应授权和服务条款。

## 19. 产品风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 免费网页数据源变更或限流 | 行情/公告中断 | 适配器隔离、健康检查、备用源和明确降级 |
| “实时”数据实际延迟 | 错误盘中决策 | 显示市场时间、延迟级别和新鲜度门禁 |
| 大模型幻觉或数值错误 | 错误事实和仓位 | 确定性计算、证据约束、结构化输出和后置校验 |
| 凯利参数高估 | 仓位过大、回撤严重 | 样本外校准、分数凯利、多重上限和拒绝机制 |
| 个人交易记录不完整 | 组合分析失真 | 对账状态、异常提示和禁止精确调仓 |
| 手机通知泄露持仓 | 隐私风险 | 默认隐私摘要、登录后查看详情 |
| 单机损坏 | 数据丢失 | 自动备份、恢复演练和可选异地加密备份 |
| 系统被理解为保证收益 | 错误预期 | 明确定位、展示不确定性和持续复盘 |
| 功能增长导致系统过重 | 运维成本上升 | 严守模块化单体和按真实瓶颈扩展 |
