## 1. 文档目的

本文档用于完整指导 UI/UX 设计师完成 WWS Adviser 的信息架构、视觉系统、组件库、响应式页面、关键交互、异常状态和设计交付。

设计师应以本文档为主要工作说明；若视觉方案与产品业务规则冲突，以产品需求中的数据质量、风险约束和建议安全规则为准。任何关键页面、状态或组件若需要偏离本文，应在设计评审时记录原因。

本轮设计需要完成：

- P0 全部页面的移动端高保真稿。
- P0 核心页面的桌面响应式高保真稿。
- 浅色、深色和关键异常状态。
- 可复用 Design Tokens 与组件库。
- 4 条核心任务流的可点击原型。
- 面向开发的尺寸、间距、状态和交互标注。

## 2. 产品体验定位

### 2.1 一句话体验

一个冷静、可信、证据充分的个人投资驾驶舱：让用户快速知道“现在发生了什么、我的风险在哪里、需要关注什么、依据是什么”，而不是制造频繁交易冲动。

### 2.2 设计关键词

- 专业
- 冷静
- 克制
- 清晰
- 可追溯
- 数据可信
- 移动高效
- 风险优先

### 2.3 应避免的风格

- 避免赌场、游戏化、霓虹、金色财富感和夸张渐变。
- 避免满屏红绿、闪烁数字和刺激交易的动效。
- 避免把大模型表现成“全知专家”或人格化荐股大师。
- 避免只给“买/卖”大按钮而隐藏条件和风险。
- 避免大面积行情表格直接缩放到手机。
- 避免用模糊的“AI 置信度”代替数据质量和统计依据。
- 避免把延迟行情、旧基金净值或缓存报告包装成实时信息。

### 2.4 体验原则

1. **行动优先，证据可展开**：首屏展示待办、风险和建议摘要，细节通过展开或详情页查看。
2. **时间永远可见**：任何行情、净值、报告和建议都必须展示其代表时间或截止时间。
3. **风险不隐藏**：硬风险、数据异常和建议失效条件必须出现在行动之前或同一视觉层级。
4. **建议是条件，不是指令**：使用“如果……则……”的结构，禁止设计成无条件交易号召。
5. **数值有上下文**：盈亏必须说明周期，仓位必须说明当前值与目标区间，价格必须说明数据状态。
6. **事实、计算、判断分开**：研究报告使用明确标签区分三类内容。
7. **移动端一手可用**：高频操作位于拇指舒适区，主要点击目标不小于 44×44px。
8. **异常优雅降级**：即使模型或数据源失败，仍清楚展示可用的持仓和确定性风险信息。

## 3. 目标用户、环境与设计基准

### 3.1 用户特征

- 单一用户，有股票/基金投资经验。
- 经常在通勤、路上、弱网环境中使用手机。
- 需要快速摘要，也会在电脑上进行深度研究和复盘。
- 对数据时效、来源和实际持仓高度敏感。
- 不需要社交、排行榜、跟单或公开分享社区。

### 3.2 设计基准尺寸

设计稿至少覆盖：

| 类型 | Figma Frame | 用途 |
| --- | --- | --- |
| 小屏手机 | 360×800 | 检查最低宽度和文本换行 |
| 标准手机 | 390×844 | 移动端主设计基准 |
| 大屏手机 | 430×932 | 检查信息密度和安全区 |
| 平板 | 768×1024 | 双栏转换验证 |
| 桌面 | 1440×1024 | 桌面主设计基准 |

### 3.3 响应式断点

| 断点 | 布局行为 |
| --- | --- |
| `< 600px` | 单列、底部导航、页面级抽屉/Bottom Sheet |
| `600–1023px` | 单列或 8 栅格双栏；底部导航可保留 |
| `≥ 1024px` | 左侧导航 + 12 栅格主内容区 |
| `≥ 1440px` | 内容最大宽度 1200px，避免无限拉宽 |

断点以内容是否可读为准，设计师可在不改变整体规则的情况下微调 16px 范围。

## 4. 信息架构

### 4.1 一级导航

移动端固定五个底部入口：

1. **首页**：组合摘要、风险、今日行动、报告入口。
2. **持仓**：持仓、自选、交易流水、账户和对账。
3. **助手**：盘中快速问询、普通问询和历史记录。
4. **研究**：公司/行业研究、报告库、研究任务。
5. **设置**：风险、数据源、模型、通知、任务、安全和备份。

桌面端使用同样的五项一级导航，呈现为 224px 左侧栏。研究下可展开“研究任务、报告库”，设置下可展开各设置子项。

## 5. 应用外壳与总体布局

### 5.1 移动端应用外壳

- 顶部状态/标题栏：56px，高度不含系统状态栏。
- 页面左右安全边距：16px；360px 小屏可降至 12px。
- 内容区底部必须预留 `72px + safe-area-inset-bottom`，防止被导航遮挡。
- 底部导航视觉高度 64px，含安全区后自适应。
- 一级页保留底部导航；二级详情页可隐藏底部导航，使用返回按钮。
- 助手输入框固定在底部导航上方；键盘弹出时导航隐藏，输入框跟随可视区域。
- 下拉刷新仅用于首页、持仓和报告列表；同时保留明确刷新按钮以适应 PWA 和无下拉环境。

### 5.2 桌面端应用外壳

- 左侧导航：224px，固定；图标 + 文本。低于 1180px 可折叠为 72px 图标栏。
- 顶部栏：64px，包含面包屑、全局搜索、数据状态、通知和用户菜单。
- 主内容最大宽度 1200px，居中；页面左右 padding 32px。
- 采用 12 栅格，列间距 24px。
- 首页建议使用 8/4 两栏：左侧组合和行动，右侧风险、任务和数据状态。
- 报告阅读使用 3/9 或 2/8/2 布局：左侧目录、正文、可选右侧证据抽屉。

### 5.3 页面标题区

一级页标题区包含：页面标题、1 行辅助说明或日期、最多 1 个主操作和 1 个次操作。移动端主操作优先放在右上角图标或页面内容中的全宽按钮，禁止塞入 3 个以上图标。

二级页标题栏包含返回、标题和溢出菜单。标题过长时单行截断，完整名称在正文首部展示。

## 6. 视觉风格

### 6.1 总体风格

采用“现代投研终端的专业感 + 消费级移动产品的轻易读性”：

- 大面积中性浅灰背景，白色卡片承载内容。
- 品牌靛蓝用于导航、选中、主按钮和信息强调。
- 少用渐变；品牌渐变只允许用于登录页/空态插画的局部背景。
- 数据表和报告强调对齐、留白和层级，不追求高密度终端感。
- 卡片边框比阴影更重要，阴影保持克制。
- 行情红绿只用于涨跌，不用于操作建议和普通成功/失败反馈。

### 6.2 品牌表达

临时产品名使用 **WWS Adviser**。Logo 建议采用抽象的“W + 路径/趋势线 + 盾牌边界”，体现分析和风险控制，不使用货币符号、火箭、K 线暴涨或金币。

品牌语气：可靠的研究助手，而非预测大师。登录页主文案建议：

> 看清持仓、风险与依据，再做决定。

### 7.3 颜色使用硬规则

- 中国市场约定：上涨红、下跌绿；设置页允许未来扩展配色，但 MVP 固定此约定。
- 红/绿旁必须同时显示 `+/-`、箭头、文字或图标，不能只靠颜色。
- 行动建议不使用市场红绿：减少用橙色、观察用琥珀、条件式增加用靛蓝、退出观察用洋红、暂停用灰色。
- 高风险洋红用于风险，不和上涨红混用。
- 大面积背景不使用高饱和红绿。

### 7.4 字体

字体栈：

```text

Microsoft YaHei, Noto Sans CJK SC, system-ui, sans-serif
```

数字开启 `font-variant-numeric: tabular-nums`，表格和卡片中的价格、金额、百分比必须使用等宽数字特性。

| 样式 | 移动端 | 桌面端 | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- | --- |
| Display | 28px | 32px | 1.2 | 700 | 资产总额、报告大标题 |
| H1 | 24px | 28px | 1.3 | 700 | 页面标题 |
| H2 | 20px | 22px | 1.35 | 600 | 大区块标题 |
| H3 | 17px | 18px | 1.4 | 600 | 卡片/章节标题 |
| Body Large | 16px | 16px | 1.6 | 400/500 | 建议摘要、重要正文 |
| Body | 14px | 14px | 1.55 | 400 | 默认正文 |
| Label | 13px | 13px | 1.4 | 500/600 | 控件、标签 |
| Caption | 12px | 12px | 1.45 | 400/500 | 时间、来源、辅助说明 |
| Micro | 11px | 11px | 1.35 | 500 | 角标，谨慎使用 |

正文不得小于 14px；只有时间、来源和角标可使用 12px。不要用 10px 塞信息。

### 7.5 间距与栅格

基础单位 4px：

| Token | 值 |
| --- | --- |
| `space.1` | 4px |
| `space.2` | 8px |
| `space.3` | 12px |
| `space.4` | 16px |
| `space.5` | 20px |
| `space.6` | 24px |
| `space.8` | 32px |
| `space.10` | 40px |
| `space.12` | 48px |

- 移动页面区块间距：24px。
- 卡片内边距：16px；复杂报告卡 20px。
- 同组元素间距：8～12px。
- 桌面 12 栅格，gutter 24px；平板 8 栅格，gutter 16px；手机 4 栅格，gutter 12px。

### 7.6 圆角、边框和阴影

| Token | 值 | 用途 |
| --- | --- | --- |
| `radius.sm` | 6px | 标签、小控件 |
| `radius.md` | 10px | 输入、按钮 |
| `radius.lg` | 14px | 普通卡片 |
| `radius.xl` | 20px | 重点卡、Bottom Sheet |
| `radius.full` | 999px | Pill、头像 |
| `shadow.1` | `0 1px 2px rgba(16,24,40,.06)` | 普通卡片可选 |
| `shadow.2` | `0 8px 24px rgba(16,24,40,.10)` | 浮层 |

卡片默认使用 1px 边框 + 极弱阴影，不使用厚重漂浮效果。

### 7.7 图标

- 使用统一线性图标库，默认 20px、线宽 1.75px。
- 导航图标 22～24px，选中态可使用填充版本。
- 风险、来源、刷新、时间、离线、锁定等语义必须有图标 + 文字。
- 不使用 emoji 作为正式功能图标。

### 7.8 动效

- 快速反馈 120～180ms；页面/弹层 200～240ms。
- 使用 ease-out 进入、ease-in 退出。
- 行情变化只允许 300ms 淡色背景提示，不闪烁、不跳动缩放。
- 报告生成进度使用平滑进度和步骤状态，不用无限转圈作为唯一反馈。
- 支持 `prefers-reduced-motion`，关闭非必要位移和数字滚动。

## 8. 数据与金融信息展示规则

### 8.1 数字格式

| 数据 | 示例 | 规则 |
| --- | --- | --- |
| 人民币金额 | `¥328,540.26` | 千分位；敏感模式显示 `¥••••••` |
| 大额摘要 | `32.85 万` | 仅摘要可用单位缩写，详情保留完整值 |
| 股票价格 | `18.42` | 按标的价格精度，不强制统一两位 |
| 基金净值 | `1.284563` | 按数据源精度，必须显示净值日期 |
| 涨跌幅 | `+2.11%` | 始终带正负号；0 显示 `0.00%` |
| 仓位 | `13.2%` | 默认一位小数；计算详情可两位 |
| 数量 | `1,500 股` / `2,345.67 份` | 单位不可省略 |
| 时间 | `10:32:15` | 盘中行情精确到秒 |
| 日期 | `2026-07-16` | 报告/详情使用完整日期 |
| 相对时间 | `3 分钟前` | 必须可点/悬停查看绝对时间 |

### 8.2 正负和空值

- 正收益显示 `+`，负收益显示 `−`（真正的数学负号或清晰短横）。
- 空数据用 `—`，不能用 `0` 代替未知。
- 不适用显示“无此指标”，样本不足显示“样本不足”，源失败显示“暂不可用”。
- 所有估算值在数字旁显示“估”或“估算”标签。
- 缓存/旧值增加“截至”时间和灰色状态，不降低透明度到难以阅读。

### 8.3 时间与来源组件

每个行情/建议/报告至少在组件底部显示：

```text
截至 10:32:15 · 延迟约 4 秒 · 来源：数据源名称
```

基金净值显示：

```text
净值日期 2026-07-15 · 2026-07-16 21:08 披露
```

“来源”可点击打开 Evidence Bottom Sheet 或桌面侧栏。多个来源显示“3 个来源”。

### 8.4 状态语义

市场状态：盘前、集合竞价、交易中、午间休市、收盘集合竞价、已收市、非交易日、临时休市。

数据状态：最新、延迟、缺失、冲突、解析失败、来源不可用、缓存副本。

任务状态：排队中、采集中、分析中、生成中、校验中、已完成、部分完成、失败、已取消。

报告状态：正常、数据不完整、待净值更新、已过期、离线副本。

## 9. 核心组件规范

### 9.1 Data Status Bar 数据状态条

**用途：** 在首页、持仓、助手和报告顶部持续表达市场状态和数据新鲜度。

**结构：** 状态圆点/图标、主状态、更新时间、异常数量、进入详情的 Chevron。

**高度：** 移动 40px；桌面可作为顶部栏中的紧凑 Pill。

**变体：**

- 正常：中性背景 + “交易中 · 更新于 10:32:15”。
- 延迟：琥珀背景 + “行情延迟 2 分 18 秒”。
- 冲突/不可用：洋红弱背景 + “部分数据不可用 · 2 项”。
- 离线：灰色斜线/离线图标 + “离线 · 显示缓存内容”。

点击进入 DATA-01，不能只弹 Toast。

### 9.2 Metric Card 指标卡

**结构：** 指标名、主数值、变化、周期/时间、可选迷你趋势线。

**规格：** 移动两列，每卡最小宽 156px，高 96～116px；桌面 3～4 列。

总资产和今日盈亏可合并为一张宽卡。盈亏颜色只作用于数值和小箭头，不染整个背景。

### 9.3 Advice Card 建议卡

这是产品最重要的组件，必须在 Figma 中提供完整 Variant。

**固定信息层级：**

1. 标的代码/名称 + 行动标签 + 风险级别。
2. 当前仓位 → 目标仓位区间。
3. 一句话条件式摘要，最多 3 行。
4. 触发条件或“为什么现在关注”。
5. 行情时间、有效期、数据状态。
6. “查看依据”和“记录操作”入口。

```text
┌────────────────────────────────┐
│ 贵州茅台 600519       [减少]    │
│ 当前 13.2%     →     目标 9–10% │
│ 若跌破 ¥1,452 且量能放大，可分批 │
│ 减少当前持仓的 20%～30%。         │
│ 触发：价格 + 量能 + 个股仓位超限   │
│ 截至 10:32:15 · 有效至 10:42      │
│ [查看 4 条依据]      [记录操作]    │
└────────────────────────────────┘
```

**行动变体：**

| 动作 | 颜色 | 图标 | 说明 |
| --- | --- | --- | --- |
| 保持 | Slate/中性 | Pause Circle | 当前处于目标区间 |
| 观察 | Amber | Eye | 等待条件，不暗示立即交易 |
| 条件式增加 | Indigo | Plus Circle | 不使用上涨红或“立即买入” |
| 减少 | Orange | Arrow Down Right | 与行情下跌绿区别 |
| 退出观察 | Magenta | Log Out/Shield Alert | 投资假设失效 |
| 暂停建议 | Gray | Shield Off | 数据不足/异常 |

**状态变体：** 默认、展开、已过期、数据延迟、已触发、已失效、已记录操作、Skeleton。

硬规则：当 `暂停建议` 时，不显示目标交易数量和醒目的行动按钮，只显示原因和可用事实。

### 9.4 Risk Alert 风险提醒

分为 Info、Warning、Critical：

- Info：需要知道但不要求立即处理。
- Warning：当日应查看。
- Critical：硬限制、重大公告、账本或数据严重异常。

Critical 提醒固定在页面重要内容之前，并包含“影响什么”和“如何处理”。禁止仅显示错误代码。

### 9.5 Position Row / Card 持仓行

移动端单行高度 72～88px，结构：

- 左：名称、代码、类型/行业小标签。
- 中：现价、涨跌幅、行情时间异常点。
- 右：市值或持仓权重，风险/建议小标。

用户可在顶部切换右侧主指标：市值、仓位、持有收益。选择在当前设备记忆。

滑动操作不作为唯一入口；可支持左滑“自选/更多”，但详情点击始终有效。

### 9.6 Evidence Link / Drawer 证据组件

正文引用使用上标编号 `[1]` 或紧凑来源 Chip。点击后：

- 移动端打开 80～92% 高度 Bottom Sheet。
- 桌面端打开 360～420px 右侧抽屉。

证据内容包含：来源等级、标题、发布主体、发布时间、引用片段、定位、原文入口、抓取时间。明确显示“事实来源”或“模型引用”。

### 9.7 Fact / Calculation / Judgment 标签

研究报告中使用：

- `事实`：蓝灰边框。
- `计算`：靛蓝边框，可展开公式和输入。
- `判断`：琥珀边框，附不确定性说明。
- `未证实`：洋红弱背景，禁止与事实混排。

标签应紧凑但不低于 20px 高，正文段落无需每句都贴标签，以段落或结论块为单位。

### 9.8 Buttons

变体：Primary、Secondary、Tertiary、Danger、Ghost/Icon。

- 移动主按钮高度 48px，桌面 40px。
- 一个视区只允许一个明显 Primary。
- “记录操作”是 Secondary；系统不提供“立即买入/立即卖出”。
- 删除交易、恢复备份使用 Danger，并要求确认。
- 禁用态必须同时说明原因；可在按钮下方显示一行帮助文本。

### 9.9 Inputs 与表单

- 输入高度 44～48px，Label 位于输入上方，不使用仅 Placeholder 的标签。
- 金额、价格、数量显示单位后缀并打开数字键盘。
- 错误在字段下就近显示；提交后焦点移动到第一个错误。
- 高级配置默认折叠，避免设置页显得复杂。
- 风险阈值输入同时显示当前值、建议范围和影响预览。

### 9.10 Tabs、Segmented Control 和 Filter Chips

- 一级内容切换使用 Tabs，例如“持仓 / 自选 / 流水”。
- 同一数据的显示方式切换使用 Segmented Control，例如“金额 / 仓位”。
- 筛选使用可水平滚动的 Filter Chips，必须有“全部”与已选数量。
- 移动端 Tabs 可吸顶；不要在一个页面嵌套三层 Tabs。

### 9.11 Bottom Sheet / Dialog

- 移动端选项、筛选、证据使用 Bottom Sheet。
- 破坏性确认、恢复备份使用 Modal/Dialog，不允许下滑手势误关闭。
- Bottom Sheet 顶部提供拖拽条和明确关闭按钮。
- 桌面对等交互使用 Dialog 或右侧 Drawer。

### 9.12 Loading、Empty、Error

- 首屏使用结构一致的 Skeleton，不用全屏 Spinner。
- 按钮提交在按钮内显示进度并防重复点击。
- 长任务展示步骤、当前阶段、开始时间和“可离开此页”。
- 空状态说明为什么为空和下一步，例如“尚未录入交易—导入 CSV 或手工添加”。
- 错误状态显示可理解原因、受影响范围、最后成功时间和重试入口。

### 9.13 Toast 与消息

- Toast 用于已完成且无需决策的轻反馈，如“交易已保存”。
- 风险、数据异常、备份失败不能只用 Toast，需保留在页面或通知中心。
- 移动 Toast 位于底部导航上方，助手页位于输入框上方。
- 同时最多显示 2 条，重复消息合并。

## 10. 页面详细设计

### 10.1 AUTH-01 登录

**目标：** 安全、简洁地进入个人系统。

**移动布局：**

1. 顶部留白 72～96px。
2. Logo、产品名和主文案。
3. 密码输入；若未来启用 Passkey，显示“使用通行密钥”。
4. 主按钮“登录”。
5. 本机/服务状态小字，不展示内部地址和版本细节。

**桌面布局：** 居中 420px 登录卡；可在左侧加入克制的品牌插画，但不使用股票暴涨图。

**状态：** 默认、密码错误、限速等待、服务离线、首次用户未初始化。错误文案不透露账户是否存在。

### 10.2 ONB-01 首次配置向导

**目标：** 在不阻塞使用的前提下完成最小可运行设置。

**步骤：**

1. 账户：账户名、初始现金、成本法说明。
2. 投资范围：A 股、ETF、公募基金默认选中。
3. 风险偏好：单标的上限、行业上限、最低现金；提供“稳健默认值”和说明。
4. 数据与模型：显示已配置的环境凭据状态；允许稍后设置。
5. 报告和通知：默认时间、隐私通知预览。
6. 完成：汇总设置和“导入第一笔交易”。

移动端每步一屏，底部固定“继续”；顶部显示 `2/6` 和进度条。允许跳过模型/通知，但首页持续显示待配置提示。

### 10.3 HOME-01 首页总览

**目标：** 30 秒内让用户了解组合状态、最高风险和今日应关注事项。

**移动内容顺序：**

1. 页面问候/业务日期 + 刷新。
2. Data Status Bar。
3. 组合摘要宽卡：总资产、今日盈亏、现金仓位、组合风险。
4. Critical/Warning 风险聚合。
5. 今日行动，最多直接展示 3 张 Advice Card；其余折叠为“查看全部”。
6. 持仓概览，展示前 5 个或异常持仓优先。
7. 最新报告卡：开市前/收市后/研究。
8. 任务状态：仅有运行中或失败任务时展示。

**桌面布局：**

- 顶部 4 张指标卡。
- 左 8 列：今日行动、持仓概览、收益趋势。
- 右 4 列：风险、数据质量、报告/任务。

**关键状态：**

- 盘前：突出开市前报告和今日观察。
- 交易中：突出行情时间、盘中风险和快捷提问。
- 收市后：突出当日盈亏和复盘。
- 非交易日：突出研究入口和最近周总结，不伪装实时。
- 空账户：显示导入/录入引导，不展示 0 元假仪表盘。
- 离线：组合摘要标记缓存时间，隐藏刷新后实时动作。

### 10.4 HOME-02 今日行动与风险

**目标：** 承接首页“查看全部”，让用户按优先级处理所有有效建议、风险和数据阻塞项。

**顶部：** 业务日期、市场状态、数据时间和刷新。使用 Tabs 切换“今日行动 / 风险”，Tab 上显示未处理数量。

**今日行动：**

- 以 Critical 风险关联的建议、已触发建议、即将过期建议、普通观察的顺序排列。
- 支持按动作、持仓/自选、行业和有效状态筛选。
- 每项使用 Advice Card；已过期和已失效默认折叠到“历史状态”。
- 支持进入建议详情和记录实际操作，不提供批量执行。

**风险：**

- 按硬限制、数据/账本、正式公告、组合暴露、普通观察分组。
- 每条显示风险值、阈值、影响标的、触发时间和处理建议。
- 同一根因影响多个标的时聚合展示，并允许展开。
- 已确认/已处理风险保留在当日历史中，不直接消失。

**空态：** “当前没有需要处理的行动”，下方仍显示最近检查时间和进入持仓/研究的次入口，不使用庆祝动画。

### 10.5 DATA-01 数据状态中心

**目标：** 解释数据是否可靠、哪里异常、哪些功能因此降级。

**布局：**

1. 总状态：正常/部分降级/严重异常。
2. 当前市场和本机时间健康。
3. 数据源卡列表：行情、交易日历、公告、基金净值、新闻。
4. 每卡展示最后成功时间、延迟、连续失败、受影响功能。
5. 数据冲突列表，可进入详情比较来源值。
6. “重新检查”主操作。

不要向普通页面暴露堆栈、HTTP 状态等内部细节；高级诊断折叠展示并支持复制诊断 ID。

### 10.6 PORT-01 持仓与自选

**顶部 Tabs：** 当前持仓 / 自选 / 流水。移动端“账户与对账”放入右上角菜单或摘要卡入口。

#### 当前持仓

- 顶部组合摘要：市值、现金、持仓数量、集中度。
- 排序：风险优先、仓位、当日涨跌、持有盈亏、名称。
- 筛选：股票、ETF、基金、行业、异常。
- 列表使用 Position Card；Critical 项置顶并标注原因。
- 浮动/底部主操作：“记录交易”。

#### 自选

- 搜索添加标的。
- 展示现价/净值、涨跌、行业、最近公告和研究状态。
- 未持有标的禁止展示“持仓建议”，只能展示观察与研究信号。

#### 桌面

使用表格 + 固定表头；首列名称、最后一列操作固定。默认列：标的、价格/净值、涨跌、数量、市值、仓位、成本、持有盈亏、建议、数据时间。允许列设置，但关键时间不可完全隐藏。

### 10.7 PORT-02 标的/持仓详情

**移动首屏：**

1. 名称、代码、市场、类型、自选星标。
2. 当前价格/净值、涨跌、时间和来源。
3. 当前仓位、市值、成本、持有盈亏。
4. 最新 Advice Card 或“暂无有效建议”。

**后续区块：**

- 价格/净值图：1日（有数据时）、1月、3月、1年、全部。
- 持仓变化与交易标记。
- 风险与目标仓位。
- 近期公告/事件。
- 基本面摘要和最新研究。
- 交易流水。

**桌面：** 顶部为行情与持仓摘要，主区 8 列图表/分析，右侧 4 列建议/风险/事件。

价格过期时图表仍可看历史，但首屏覆盖“行情已延迟”状态，建议卡自动变为暂停。

### 10.8 TX-01 交易流水

**移动：**

- 顶部月份选择和筛选按钮。
- 流水按日期分组，卡片展示方向、标的、数量×价格、费用和现金影响。
- 待确认基金交易使用独立状态标签。
- 点击进入详情/编辑；修改过的流水显示审计标记。
- 底部主按钮“记录交易”，次入口“导入 CSV”。

**桌面：** 表格、日期范围、品种/类型筛选、导入和导出。底部或侧栏显示筛选结果汇总。

**空态：** 插画 + “还没有交易记录” + 两个入口：导入 CSV、手工记录。

### 10.9 TX-02 新建/编辑交易

**表单顺序：**

1. 交易类型：买入、卖出、申购、赎回、分红、费用、拆分、现金调整等。
2. 标的搜索；现金调整时隐藏。
3. 成交日期时间/确认日期。
4. 数量/份额。
5. 单价/净值；基金可标“待确认”。
6. 手续费、税费，可展开自动估算说明。
7. 现金影响预览。
8. 备注。

底部固定“保存交易”。保存前显示计算摘要；卖出超出可用数量、价格精度错误等在字段级阻止。编辑历史流水时顶部显示“修改将重算此日期后的持仓”，保存前二次确认。

现金调整、删除和恢复不是普通主按钮，应放入更多菜单并要求原因。

### 10.10 TX-03 CSV 导入向导

**步骤：** 上传 → 字段映射 → 校验预览 → 冲突处理 → 确认导入 → 结果。

#### 移动端

- 上传支持文件选择，不强求拖拽。
- 字段映射使用逐字段卡片，不展示超宽表。
- 预览只展示关键 5 列，点击行查看完整字段。
- 顶部固定统计：总计、有效、警告、错误、重复。

#### 桌面端

- 可使用完整数据表、批量选择和侧栏错误详情。

**错误颜色与图标并用。** 只有错误行可导出为修正 CSV。确认页必须明确“将新增 N 条、跳过 N 条重复、拒绝 N 条错误”。

### 10.11 ACC-01 账户与对账

**结构：**

1. 账户概况和最后对账时间。
2. 系统计算值与用户确认值的并列比较。
3. 差异列表：现金、数量、成本。
4. “标记已对账”或“创建对账调整”。
5. 历史对账记录。

未对账状态使用持续 Warning，但不阻止查看历史和研究；明确说明“系统将暂停精确调仓数量”。创建调整必须填写原因。

### 10.12 CHAT-01 助手首页/对话

**目标：** 快速提出自然语言问题，同时始终看到使用了什么市场时间和持仓上下文。

**初始页：**

- 市场状态和数据时间。
- 快捷问题 Chips：`现在最大的风险？`、`某持仓是否需要减仓？`、`如果加仓会怎样？`、`解释今日盈亏`。
- 最近询问。
- 输入框支持标的搜索/提及。

**对话页布局：**

```text
┌────────────────────────────┐
│ 助手      交易中 · 10:32:15 │
├────────────────────────────┤
│ 你：现在是否需要减仓？       │
│                            │
│ [行情与持仓上下文条]         │
│ ┌────────────────────────┐ │
│ │ 结构化 Advice Card      │ │
│ └────────────────────────┘ │
│ 分析说明正文……              │
│ [依据 4] [计算过程]          │
│ 本建议有效至 10:42           │
├────────────────────────────┤
│ 输入问题……        发送       │
└────────────────────────────┘
```

**关键规则：**

- AI 回答不使用普通聊天气泡承载核心建议，核心建议必须使用 Advice Card。
- 回答开始处显示数据上下文，不藏在最底部免责声明。
- 生成时分阶段显示“获取行情 → 检查持仓 → 运行风险规则 → 生成解释”。
- 12 秒未完成时先展示确定性结果；模型文字完成后增量补充。
- 行情过期时输入框上方常驻提示“当前无法提供即时交易数量”。
- 历史回答明确标记“已过期”，不能看起来仍然有效。

### 10.13 CHAT-02 建议详情

**结构：**

1. 完整 Advice Card。
2. 当前 vs 目标仓位可视化：水平区间条，不使用仪表盘。
3. 建议数量计算（数据合格时）。
4. 触发条件和失效条件。
5. 风险约束调整轨迹。
6. 凯利计算过程（如适用）：理论值、折扣、约束、最终区间。
7. 事实和证据。
8. “记录我的实际操作”表单。

凯利区块默认折叠，摘要写“理论 18.6% → 风控后 2.5%～3.0%”，展开后显示每一步；禁止用炫目的仪表盘暗示精确科学性。

### 10.14 LIB-01 研究与报告库

顶部 Segmented Control：报告 / 研究任务。

**报告列表：**

- 类型筛选：开市前、收市后、公司、行业。
- 时间、标题、状态、数据截止时间、关键结论摘要。
- 开市前/收市后按交易日分组；研究按主题分组。
- 离线可用报告显示下载/缓存图标。

**研究任务：** 运行中、待处理、失败、已完成。运行中展示阶段和预计不是承诺的“通常耗时”，不要显示伪精确剩余秒数。

主操作“新建研究”。

第一步选择“公司研究 / 行业研究”，随后动态表单：

#### 公司研究

### 10.16 RES-02 研究任务进度

**步骤时间线：** 收集正式披露 → 收集行业/新闻 → 提取证据 → 计算指标 → 生成草稿 → 引用校验 → 完成。

### 10.17 REP-01 开市前报告

**报告共用框架：** 三类报告顶部都包含返回、报告类型/标题、状态、业务日期、生成时间、数据截止时间和更多菜单。更多菜单提供“保存离线副本、导出、复制链接/文本、查看生成信息”；移动端滚动后缩为 Sticky 标题栏。报告底部统一包含来源清单、数据/规则/模型版本和个人研究声明。导出或分享前提示检查敏感持仓信息。

**移动信息顺序：**

1. 报告标题、业务日期、生成/截止时间和完整度。
2. 一屏执行摘要：组合风险、重大事项数量、建议动作分布。
3. Critical 风险。
4. 今日行动 Advice Cards。
5. 隔夜公告/行业事件。
6. 停复牌、分红、解禁等日历。
7. 组合暴露和现金。
8. 今日观察清单。
9. 来源和生成信息。

页面底部不是“执行全部”，只提供“记录操作”或“返回持仓”。

### 10.18 REP-02 收市后复盘

**移动信息顺序：**

1. 当日盈亏、基准差和数据完整度。
2. 盈亏贡献 Top/Bottom。
3. 当日交易执行摘要。
4. 建议 vs 实际操作。
5. 风险变化。
6. 行为偏差和复盘问题。
7. 次日待办。
8. 来源和生成信息。

“做得好/做得差”避免道德化，使用中性文案：“符合计划”“偏离计划”“待确认原因”。

### 10.19 REP-03 公司/行业研究报告

#### 移动

- 顶部 Sticky：返回、标题、目录、更多。
- 首屏：研究对象、数据截止时间、结论摘要、完整度。

## 11. 核心任务流

### 11.1 每日开市前查看

```text
收到隐私通知
  → 打开 PWA 并登录
  → 首页看到报告完成 + 风险数量
  → 打开开市前报告
  → 阅读一屏摘要
  → 展开最高风险/建议
  → 查看证据和失效条件
  → 选择“记录计划”或返回持仓
```

原型必须覆盖：正常报告、公告源不完整、无行动建议三种情况。

### 11.2 盘中快速问询

```text
助手 → 选择持仓/输入问题
  → 显示正在获取行情和检查风险
  → 返回结构化 Advice Card
  → 查看计算/证据
  → 记录实际操作
```

原型必须覆盖：行情最新、行情过期导致暂停建议、模型慢先返回确定性结果。

### 11.3 记录交易并对账

```text
持仓 → 记录交易
  → 选择类型和标的
  → 输入数量/价格/费用
  → 查看现金与持仓预览
  → 保存
  → 持仓重算
  → 查看结果或处理对账差异
```

原型必须覆盖：正常买入、卖出超量错误、编辑历史流水重算提醒。

### 11.4 发起公司研究

```text
研究 → 新建研究 → 公司
  → 选择公司、问题、对标和深度
  → 确认数据/模型/费用
  → 任务进度
  → 收到完成通知
  → 阅读摘要和关键风险
  → 打开引用和完整报告
```

原型必须覆盖：正常完成、部分数据缺失、任务失败后重试。

## 12. 图表与可视化规范

### 12.1 通用规则

- 图表必须有标题、周期、单位、数据截止时间和来源入口。
- 移动端默认高度 180～240px；桌面 240～320px。
- 横轴/纵轴标签保持可读，不能用极小字体塞满。
- Tooltip 在手机使用点击锁定，再次点击或关闭按钮退出。
- 图例可点击筛选，隐藏后保留状态提示。
- 空、样本不足、数据延迟和部分缺口必须有图内状态。
- 不使用 3D 图表、过度面积渐变、炫目动效和难比较的仪表盘。

### 12.2 推荐图表

| 场景 | 图表 | 规则 |
| --- | --- | --- |
| 总资产趋势 | 折线图 | 同时显示基准时用不同线型，不只靠颜色 |
| 当日/累计盈亏 | 折线或柱状 | 正负跨零轴清晰 |
| 持仓分布 | 排序水平条 | 优先于饼图，直接标仓位 |
| 行业暴露 | 水平条 | 显示行业上限线 |
| 收益贡献 | 正负水平条/瀑布图 | Top/Bottom 默认 5 项 |
| 当前 vs 目标仓位 | 区间条 | 显示当前点、目标带和硬上限 |
| 风险变化 | 小倍数折线/条形 | 标注规则阈值 |
| 价格/净值 | 折线/K 线 | 手机默认折线，K 线按需展开 |
| 财务趋势 | 柱线组合 | 最多 2 个量纲，避免双轴滥用 |
| 同业对比 | 排序条/点图 | 避免雷达图作为精确比较 |
| 情景估值 | 区间/瀑布 | 显示假设和非预测声明 |

### 12.3 饼图限制

只在持仓/资产构成类别 ≤ 6 时使用 Donut；超过 6 项归为“其他”并提供明细。Donut 中心显示总值或现金比例，不显示无意义装饰。

### 12.4 数据异常可视化

数据缺口使用断线或阴影区域，不做平滑插值伪造趋势。过期数据在图表右上角显示灰色“截至日期”，严重异常时显示覆盖层但保留历史图可查看。

## 13. 内容与文案规范

### 13.1 语气

- 客观、直接、克制。
- 解释原因，不夸大确定性。
- 使用“建议关注”“条件满足时可考虑”“数据不足，暂停建议”。
- 不使用“稳赚”“必涨”“抄底机会”“梭哈”“强烈推荐”等词。
- 不用责备式复盘，如“你犯了错误”；改为“本次操作偏离预设计划”。

### 13.2 建议句式

推荐格式：

```text
结论：当前仓位高于风险目标，建议观察减仓条件。
条件：若价格跌破 ¥18.05 且量能继续放大，可减少 20%～30%。
失效：若公告澄清风险且仓位回到目标区间，本建议失效。
有效期：截至 10:42 或条件先失效。
```

### 13.3 数据质量文案

- “行情更新于 10:32:15，延迟约 4 秒。”
- “行情已超过 90 秒，本次只展示持仓风险，不提供交易数量。”
- “公告源暂不可用，不能确认是否存在新的重大公告。”
- “基金最新披露净值为 2026-07-15，本日收益待净值发布后更新。”

### 13.4 按钮文案

使用明确动词：保存交易、查看依据、开始研究、重新检查、立即备份、从此步骤重试。避免“确定”“好的”作为缺少上下文的主按钮。

## 14. 全局状态设计

### 14.1 加载

- 页面第一次加载：结构 Skeleton。
- 刷新已有数据：保留旧内容，顶部/局部显示刷新，不清空页面。
- 行情更新：只刷新受影响数字和时间。
- 长任务：步骤时间线 + 可离开提示。

### 14.2 空状态

必须设计：

- 尚无账户/持仓。
- 有账户但无交易。
- 尚无自选。
- 尚无报告/研究任务。
- 无匹配搜索结果。
- 当前没有风险或建议。

“没有风险”使用平静文字，不使用庆祝动画；它只代表当前规则未触发。

### 14.3 异常状态

必须设计：

- 完全离线。
- 单一数据源失败。
- 多源冲突。
- 行情过期。
- 模型不可用。
- 报告部分完成。
- 任务失败可重试。
- 数据库/存储只读。
- 未登录/会话过期。

每个异常说明：发生了什么、哪些内容仍可信、哪些功能暂停、用户下一步是什么。

### 14.4 离线状态

- 顶部常驻离线条。
- 缓存报告标题旁显示“离线副本”。
- 隐藏/禁用实时刷新、交易写入和盘中建议，并说明需联网。
- 允许查看已缓存报告，不将其时间更新为当前时间。
- 恢复网络后显示“已恢复连接”，由用户确认刷新敏感页面或自动刷新只读摘要。

### 14.5 会话过期

保留未提交的非敏感表单草稿，弹出重新登录；交易、恢复等敏感表单不在浏览器长期存储。重新认证成功后回到原页面并重新校验数据。

## 15. 可访问性

设计目标至少满足 WCAG 2.2 AA 的关键要求：

- 正文对比度 ≥ 4.5:1，大字 ≥ 3:1。
- 触控目标 ≥ 44×44px。
- 所有功能可通过键盘操作，焦点顺序与视觉顺序一致。
- Focus Ring 明显，不能因美观移除。
- 图表提供文字摘要或数据表入口。
- 红绿、风险级别、任务状态均有图标/文字冗余编码。
- 表单 Label、错误和帮助信息有明确关联。
- Modal 打开后焦点锁定，关闭后返回触发元素。
- 支持系统字体放大；200% 缩放下核心流程不丢失。
- 支持 Reduced Motion。
- 图标按钮必须有可访问名称和可见 Tooltip（桌面）。

设计师需在 Figma 标注阅读顺序、焦点顺序和图表替代说明。

## 16. 隐私与安全体验

### 16.1 隐私模式

顶部用户菜单提供快速“隐藏金额”开关。开启后：

- 金额显示为 `••••••`，但百分比是否隐藏由二级设置决定。
- 图表纵轴金额隐藏，趋势形状可保留。
- 通知预览立即切换为隐私模式。
- 截图分享入口默认提示检查敏感信息。

### 16.2 危险操作

以下操作必须二次确认：删除/冲销交易、创建对账调整、修改硬风险、恢复备份、清除全部本机缓存、撤销全部会话。

恢复备份额外要求重新认证和输入确认文字。普通浏览和报告生成不滥用确认弹窗。

### 16.3 敏感设置

- API Key 只显示“已配置/未配置”和引用名，不能复制明文。
- 诊断信息默认脱敏。
- 外部模型数据策略用人类可理解的例子解释将发送什么。

## 17. 深色模式

深色模式需要单独设计以下关键页面：HOME-01、PORT-02、CHAT-01、REP-03、SET-03。

要求：

- 默认跟随系统，可在设置中固定浅色/深色。
- 图表背景与卡片一致，不出现纯黑大块。
- 上涨/下跌和风险色按深色 Token 使用，保证可读。
- 图片/PDF 原文不强制反色；使用中性容器承载。
- 阴影在深色模式弱化，主要依靠边框和层级背景。
- Skeleton 和禁用态仍清晰，不与正常内容混淆。

### 18.3 必交组件 Variant

- Button：5 类型 × Default/Hover/Pressed/Focus/Disabled/Loading。

- Position Card：Normal/Up/Down/Alert/Stale/Skeleton。
- Report Status：Normal/Partial/Pending/Expired/Offline。
- Job Progress：Queued/Running/Partial/Failed/Completed/Cancelled。

### 18.5 可点击原型

### 18.6 开发标注

每个关键页面标注：

- Frame 与内容最大宽度。
- 间距、栅格和吸顶/固定行为。
- 组件 Variant 和状态切换条件。
- 文本截断、换行和超长边界。
- 数字格式、空值、过期值和隐私值。
- 图表坐标、Tooltip、图例和异常状态。
- 页面进入、刷新、提交、失败和返回行为。
- Mobile/Desktop 的重排规则，而非只给两张无关系截图。

## 19. 设计验收标准

### 19.1 完整性

- [ ] 页面清单中的 P0 页面均有设计。
- [ ] 每个 P0 页面至少覆盖默认、加载、空和关键异常状态。
- [ ] 四条核心流程含正常和失败路径。
- [ ] 浅色、深色和离线状态完整。

### 19.2 业务准确性

- [ ] 任意行情、净值、建议和报告都能看到代表时间。
- [ ] 过期/缺失数据不会呈现为实时。
- [ ] 暂停建议不显示具体交易数量。
- [ ] Advice Card 包含动作、仓位区间、条件、失效和有效期。
- [ ] 事实、计算、判断和未证实信息可区分。
- [ ] 凯利界面展示调整过程，不用模型置信度代替统计概率。
- [ ] 公募基金净值日期与披露时间区分。

### 19.3 一致性

- [ ] 行情涨跌红绿与操作/风险颜色不混用。
- [ ] 数字、单位、日期、空值和估算标识一致。
- [ ] 移动与桌面使用相同组件语义和页面层级。
- [ ] 所有状态来自组件 Variant，避免页面自行创造近似样式。

### 19.4 可用性

- [ ] 360px 宽度核心流程无页面级横向滚动。
- [ ] 手机主要操作可单手触达，目标 ≥ 44px。
- [ ] 首页 30 秒内可识别最高风险和今日行动。
- [ ] 盘中回答首先展示数据时间和结构化建议。
- [ ] 长报告支持目录、折叠、引用抽屉和回到顶部。
- [ ] 恢复、删除等危险操作不会被误触。

### 19.5 可访问性和交付质量

- [ ] 颜色对比达到目标，状态不只依赖颜色。
- [ ] Focus、键盘、阅读顺序和 Reduced Motion 有说明。
- [ ] Figma 使用 Variables、Auto Layout 和规范命名。
- [ ] 设计稿包含真实长度中文、长名称、极端数值和多来源样例。
- [ ] 设计师与开发共同完成一次组件和响应式走查。

## 21. UI 设计完成定义（Definition of Done）

UI 设计工作只有在以下条件全部满足时完成：

1. P0 页面、状态、响应式和深色模式按本文交付。
2. Design Tokens 与组件库可被开发直接映射实现。
3. 四条核心流程原型通过产品业务规则走查。
4. 使用包含真实长度中文、长股票/基金名、极端盈亏、过期行情和多来源的测试数据验证。
5. 关键页面完成移动真机预览，不只在 Figma 桌面查看。
6. 产品确认信息层级，开发确认布局和组件可实现性。
7. 可访问性、隐私模式、离线和危险操作完成专项检查。
8. 所有未解决问题记录在设计文件 Readme，标注负责人和是否阻塞开发。
