## 0. 问题与根因（全部已查实）

### P-1 数字小数位超长（持仓成本等）

- **根因**：`PositionRow.vue:43` 裸插值 `成本 {{ avgCost }}`——后端 MWAC 返回全精度 Decimal 字符串（如 `12.345678901234567`）直出页面。`Portfolio.vue:62/110` 还存在 `formatMoney(mv.toFixed(2))` 这类先 toFixed 再格式化的错用（绕过但语义错）。
- **推断范围**：不止持仓成本一处，需要**全页面数字渲染审计**（凡 `{{ }}` 直出数值字段均为嫌疑）。
- **为什么没拦住**：ENFORCEMENT_CONTRACT 有 `formatMoney/formatPercent`（语义正确且部分页面在用），但没有 ESLint 规则**强制**数字字段必须过格式化函数——契约是"提供了工具"，不是"禁止绕过"。

### P-2 「记录交易」点击无效

- **根因**：`Portfolio.vue:71` 的 `recordTrade()` 是**空函数占位**（`// TODO(后续波次)`，Phase 1 波7 的占位）。视觉批次 V4 交付了功能完整的 `/transactions/new`（TxNew.vue：表单校验、幂等提交、成功回流水页都好），**但没回头把这个入口按钮接上路由**。服务器日志证实：48h 内零笔 `POST /api/v1/transactions`——点击连请求都没发出。
- **测试为什么通过（诚实回答）**：
  1. 前端 36 例 vitest 测的是**组件与 composable 单元**（useJobStatus、reportCache 等），没有浏览器端到端测试——"点按钮→跳转→发请求"链路零覆盖；
  2. 视觉批次走查 DoD 是"三截图对比基准卡"——**视觉验收不含交互验收**，截图里按钮长得对但点不动；
  3. 后端 439 例测试管 API 契约（`POST /transactions` 本身是通的），UI 到 API 的接线无人验证；
  4. 流程缺陷：V4 新建页面与 V3 既有页面的**入口可达性**不在任何验收清单里。

### P-3 研究 / 盘中建议"缺数据跑不通"

两条独立根因，都是"设计内行为但用户呈现为跑不通"：

- **研究 `insufficient_evidence`**：
  a) 9/9 的失败任务是公告正文修复（fabcf96）**之前**的旧记录，之后无重跑；数据侧已就绪（603823 已有 46/50 真实正文，最大 12.7KB）；
  b) **结构性缺口**：`data_maintenance` 定时任务只采持仓日线（15:20），**公告采集没有常态化**——目前全库只有 603823/600519 有人工采过的语料，研究任何其他标的必然零证据。UI 也不预告"该标的语料 N 条"，用户只能提交后吃失败。
- **盘中建议恒 suspend（`no_calibrated_signal`）**：breakout-20 校准有效（至 2026-12），但**信号只对校准覆盖的标的池生效**——用户持仓多数标的（600127/000708/600722/000807…）不在已校准信号内 → 每次问询都是 `no_calibrated_signal` 降级。这是风控设计（无校准不给凯利），但 UI 把原因埋在 reasons_json 里，用户看到的就是"没结果"。

### P-4 UI 观感糙（"上个世纪的网页"）

- **排除项**：图标是 UnoCSS presetIcons 构建期内联（不依赖外网字体，非图标缺失）；字体栈已配（Inter→PingFang→雅黑）。
- **真实根因**（按贡献度排序）：
  1. P-1 的数字溢出直接破坏卡片/表格排版（超长小数把行撑爆）；
  2. 视觉批次 V3 做的是**布局结构对齐**（区块顺序/密度/层级），没做**视觉精修**：无字重对比（全是 400/500，缺标题/数字的 600/700 层次）、无过渡动效、无骨架屏（加载白屏跳动）、空态是纯文字、卡片无阴影层次、表单聚焦态弱；
  3. Windows/Android 下 fallback 到雅黑/系统字体，无 `-webkit-font-smoothing` 调优，数字与中文混排观感进一步劣化；
  4. 深色模式只做了 token 映射，未做精修（对比度/层次）。
